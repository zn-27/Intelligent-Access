● Q-Learning 升级详细说明

  ---
  一、崩溃修复（最重要）

  文件: ofswitch13-learning-controller.cc 第932行

  问题:
  static int lastAction;  // 未初始化，值是随机的垃圾值

  修复:
  static int lastAction = 0;  // 明确初始化为0

  原理: C++中静态局部变量如果不初始化，其值是未定义的。当程序使用这个随机值作为
  数组索引或进行其他操作时，可能导致内存访问错误从而崩溃。

  ---
  二、网络状态扩展

  文件: ofswitch13-learning-controller.h

  改进前:
  struct NetworkState {
      float averageNodeDistance;  // 仅平均距离
      double totalThroughput;
      double maxLossRate;
  };

  改进后:
  struct NetworkState {
      float averageNodeDistance;  // 节点平均距离
      float distanceVariance;     // 新增：节点分散度（方差）
      double totalThroughput;
      double maxLossRate;
  };

  方差计算逻辑 (在 EvaluateNetworkState() 中):
  // 存储所有节点对的距离
  std::vector<float> distances;

  // 计算方差
  if (distances.size() > 1) {
      float sumSquaredDiff = 0.0f;
      for (float d : distances) {
          // 每个距离与平均值的差的平方
          sumSquaredDiff += (d - state.averageNodeDistance) * (d -
  state.averageNodeDistance);
      }
      state.distanceVariance = sumSquaredDiff / distances.size();
  }

  意义:
  - 平均距离=30米，方差=10 → 节点分布均匀
  - 平均距离=30米，方差=500 → 有的节点很近，有的很远（分散）
  - 方差帮助我们区分这两种完全不同的网络拓扑

  ---
  三、状态编码升级（2位→3位）

  文件: ofswitch13-learning-controller.cc 的 StateToId() 函数

  改进前 (2位编码，4个状态):
  int distBit = (state.averageNodeDistance <= 25.0f) ? 1 : 0;  // 距离位
  int lossBit = (state.maxLossRate <= 0.05) ? 0 : 1;           // 丢包位
  return (lossBit << 1) | distBit;  // 组合成 0,1,2,3

  改进后 (3位编码，8个状态):
  int distBit = (state.averageNodeDistance <= 25.0f) ? 1 : 0;  // bit0: 距离
  int varBit = (state.distanceVariance > 100.0f) ? 1 : 0;      // bit1: 
  方差（新增）
  int lossBit = (state.maxLossRate > 0.05) ? 1 : 0;            // bit2: 丢包
  return (lossBit << 2) | (varBit << 1) | distBit;  // 组合成 0-7

  五、移除无用动作

  改进前:
  // 探索时
  return rand() % 2;  // 只返回0或1，永远不会返回2(KEEP)

  // 利用时
  for (int a = 1; a < 3; a++)  // 检查动作1和2

  改进后:
  // 定义动作枚举
  enum Action { MULTI = 0, ADHOC = 1 };
  static constexpr int ACTION_COUNT = 2;

  // 探索时
  return rand() % ACTION_COUNT;  // 更清晰的意图

  // 利用时
  for (int a = 1; a < ACTION_COUNT; a++)  // 只检查有效的2个动作

  问题分析: 原代码的KEEP动作(index=2)在探索时永远不会被选中(rand()%2只返回0或1)
  ，但在利用时会检查它，导致逻辑不一致。

  六、经验回放（Experience Replay）

  原理图:
  传统学习:
    经验1 → 学习 → 丢弃
    经验2 → 学习 → 丢弃
    经验3 → 学习 → 丢弃
    (经验之间高度相关，容易过拟合)

  经验回放:
    经验1 → 存入缓冲区
    经验2 → 存入缓冲区
    ...
    经验10 → 存入缓冲区 → 随机抽取5条重新学习
    (打破数据相关性，提高学习效率)

  新增数据结构:
  struct Experience {
      NetworkState state;      // 执行动作前的状态
      int action;              // 执行的动作
      double reward;           // 获得的奖励
      NetworkState nextState;  // 执行动作后的状态
  };

  std::deque<Experience> replayBuffer;  // 循环缓冲区
  static constexpr size_t MAX_BUFFER_SIZE = 1000;  // 最多存1000条

  Update()中的回放逻辑:
  void NetworkModeQLearning::Update(...) {
      // 1. 存储新经验
      Experience exp = {state, action, reward, newState};
      replayBuffer.push_back(exp);
      if (replayBuffer.size() > MAX_BUFFER_SIZE) {
          replayBuffer.pop_front();  // 超出容量则移除最旧的
      }

      // 2. 标准Q表更新
      // ...

      // 3. 每10条经验回放一次
      if (replayBuffer.size() >= 10 && replayBuffer.size() % 10 == 0) {
          ReplayBatch(5);  // 随机抽5条重新学习
      }
  }

  ReplayBatch()实现:
  void NetworkModeQLearning::ReplayBatch(int batchSize) {
      double replayAlpha = alpha * 0.5;  // 回放时用更小的学习率

      for (int i = 0; i < batchSize; ++i) {
          // 随机选择一条历史经验
          int idx = rand() % replayBuffer.size();
          const Experience& exp = replayBuffer[idx];

          // 用这条经验更新Q表
          int stateId = StateToId(exp.state);
          int newStateId = StateToId(exp.nextState);
          double qPredict = qTable[stateId][exp.action];
          double qTarget = exp.reward + gamma * max(qTable[newStateId]);
          qTable[stateId][exp.action] += replayAlpha * (qTarget - qPredict);
      }
  }

  七、切换惩罚（Switching Cost）

  问题: Q-learning可能频繁切换模式，造成网络抖动
  时间0s: MULTI
  时间3s: ADHOC  ← 切换
  时间6s: MULTI  ← 又切换
  时间9s: ADHOC  ← 再切换
  （频繁切换对网络稳定有害）

  解决方案: 切换时扣除奖励

  新增成员:
  int m_lastAction = -1;  // 记录上一次的动作，-1表示第一次
  static constexpr double SWITCHING_COST = 0.1;  // 切换惩罚值

  在PeriodicDecisionMaking()中应用:
  if (!isFirstRun) {
      double reward = CalculateReward();

      // 新增：如果动作改变了，扣除惩罚
      if (m_lastAction != -1 && m_lastAction != lastAction) {
          reward -= SWITCHING_COST;  // 扣除0.1
          std::cout << "[切换惩罚] 动作改变，扣除 " << SWITCHING_COST <<
  std::endl;
      }

      m_networkQLearning.Update(lastState, lastAction, currentState, reward);
  }

  效果: Q-learning会学到"切换有代价"，从而减少不必要的切换

  八、智能初始化

  问题: 原Q表全为0，需要大量探索才能学到有效策略

  解决方案: 根据网络常识预设初始偏向

  void NetworkModeQLearning::InitializeQTable() {
      // 状态1 (近+低方差+好丢包): 节点近且集中，质量好 → 偏向用MULTI模式
      qTable[1][MULTI] = 0.3;

      // 状态6 (远+高方差+差丢包): 节点远且分散，质量差 → 偏向用ADHOC模式
      qTable[6][ADHOC] = 0.3;

      // 状态7 (近+高方差+差丢包): 分散且质量差 → 偏向用ADHOC模式
      qTable[7][ADHOC] = 0.3;
  }

  为什么这样设置:

  ┌──────┬────────────┬──────────┬──────────────────────────────┐
  │ 状态 │  网络情况  │ 偏向模式 │             原因             │
  ├──────┼────────────┼──────────┼──────────────────────────────┤
  │ 1    │ 近+集中+好 │ MULTI    │ 基站覆盖良好，用集中式更高效 │
  ├──────┼────────────┼──────────┼──────────────────────────────┤
  │ 6,7  │ 远/分散+差 │ ADHOC    │ 基站覆盖差，用自组网更可靠   │
  └──────┴────────────┴──────────┴──────────────────────────────┘

  九、完整的Q-Learning流程图

  ┌─────────────────────────────────────────────────────────────┐
  │                    PeriodicDecisionMaking()                  │
  │                      (每3秒执行一次)                          │
  └─────────────────────────────────────────────────────────────┘
                                │
                                ▼
  ┌─────────────────────────────────────────────────────────────┐
  │  1. 评估当前网络状态                                          │
  │     EvaluateNetworkState() → {距离, 方差, 吞吐, 丢包}         │
  └─────────────────────────────────────────────────────────────┘
                                │
                                ▼
  ┌─────────────────────────────────────────────────────────────┐
  │  2. 结算上一轮动作（如果不是第一次）                           │
  │     a. 计算奖励 = CalculateReward()                          │
  │     b. 如果动作改变，扣除 SWITCHING_COST                      │
  │     c. 调用 Update() 更新Q表并存储经验                        │
  │     d. 每10次经验触发回放                                     │
  └─────────────────────────────────────────────────────────────┘
                                │
                                ▼
  ┌─────────────────────────────────────────────────────────────┐
  │  3. 选择新动作                                               │
  │     ChooseAction(state)                                      │
  │     - 动态ε：丢包高→探索多，丢包低→探索少                      │
  │     - ε概率随机探索，(1-ε)概率选择最优动作                     │
  └─────────────────────────────────────────────────────────────┘
                                │
                                ▼
  ┌─────────────────────────────────────────────────────────────┐
  │  4. 执行动作                                                 │
  │     ExecuteSwitchingAction(action)                           │
  │     - action=0: MULTI模式                                    │
  │     - action=1: ADHOC模式                                    │
  └─────────────────────────────────────────────────────────────┘
                                │
                                ▼
  ┌─────────────────────────────────────────────────────────────┐
  │  5. 记录状态供下次使用                                        │
  │     m_lastAction = 上一次动作                                 │
  │     lastState = 当前状态                                     │
  │     lastAction = 本次动作                                    │
  └─────────────────────────────────────────────────────────────┘
                                │
                                ▼
                           3秒后重复

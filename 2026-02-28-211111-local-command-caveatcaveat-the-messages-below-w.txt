● 根据代码分析，OFSwitch13LearningController 是一个基于 OpenFlow 1.3 协议的 SDN
  学习型控制器，它实现了以下功能：

  核心功能总结

  1. 二层/三层学习与转发

  - L2 学习：自动学习 MAC 地址到端口的映射
  - L3 学习：自动学习 IP 地址到 (MAC, 端口) 的映射
  - 支持 ARP 包处理（代理 ARP 响应）
  - 动态下发流表规则到交换机

  2. 多交换机拓扑管理

  - 硬编码了 3 个交换机 (sw1, sw2, sw3) 的互联端口映射
  - 支持跨域路由：通过 BFS 最短路径算法找到下一跳端口
  - 自动识别子网并维护子网-交换机映射表

  3. 主机信息管理

  - HostInfo 结构体存储：IP、MAC、端口
  - HandleAdhocExtStaInfo: 处理自定义的 STA 信息上报
  - HandleHostInfo: 手动初始化预定义主机信息

  4. Q-Learning 智能网络模式切换 ⭐

  这是最核心的智能决策模块：

  状态空间 (4种):
  - 距离: 远/近 (阈值 25m)
  - 丢包: 好/差 (阈值 5%)

  动作空间 (3种):
  - 0: MULTI 模式 (基础设施模式)
  - 1: ADHOC 模式 (自组织模式)
  - 2: KEEP (保持现状)

  状态离散化 (StateToId):

  int NetworkModeQLearning::StateToId(const NetworkState& state) {
      // 维度1: 距离 (0=远, 1=近) - 阈值 25m
      int distBit = (state.averageNodeDistance <= 25.0f) ? 1 : 0;

      // 维度2: 丢包 (0=好≤5%, 1=差>5%)
      int lossBit = (state.maxLossRate <= 0.05) ? 0 : 1;

      // 组合状态 ID: 0~3
      return (lossBit << 1) | distBit;
  }

  动作执行逻辑:

  void ExecuteSwitchingAction(int action) {
      switch (action) {
          case 0: // MULTI
              if (m_currentMode != 0) {
                  // ADHOC -> MULTI
                  m_currentMode = 0;
              }
              break;
          case 1: // ADHOC  
              if (m_currentMode != 1) {
                  SetRPtoAll();           // 设置路由优先级
                  ChangeDeviceLogical(1); // 切换设备逻辑
                  m_currentMode = 1;
              }
              break;
          case 2: // KEEP
              // 无操作
              break;
      }
  }

  4. 策略选择 (Epsilon-Greedy + 动态调整)

  核心创新点 - 动态 ε 调整:

  int ChooseAction(const NetworkState& state) {
      // 根据丢包率动态计算探索率
      double dynamicEpsilon;

      if (state.maxLossRate <= 0.05) {        // 稳定态: ≤5%
          dynamicEpsilon = baseEpsilon * 0.5;  // 0.2 × 0.5 = 0.1 (少探索)
      }
      else if (state.maxLossRate <= 0.20) {   // 轻度拥塞: 5%~20%
          dynamicEpsilon = baseEpsilon * 1.5;  // 0.2 × 1.5 = 0.3 (中等探索)
      }
      else {                                   // 重度拥塞: >20%
          dynamicEpsilon = baseEpsilon * 3.0;  // 0.2 × 3.0 = 0.6 (多探索)
      }

      // 限制范围 [0, 1]
      dynamicEpsilon = min(1.0, max(0.0, dynamicEpsilon));

      // Epsilon-Greedy 探索
      if (rand() / RAND_MAX < dynamicEpsilon) {
          return rand() % 2;  // 随机探索 (只选 MULTI 或 ADHOC)
      }

      // 利用: 选择 Q 值最大的动作
      int bestAction = 0;
      double maxQ = qTable[stateId][0];
      for (int a = 1; a < 3; a++) {
          if (qTable[stateId][a] > maxQ) {
              maxQ = qTable[stateId][a];
              bestAction = a;
          }
      }
      return bestAction;
  }

  5. 奖励函数设计 ⭐

  这是整个 Q-Learning 的核心：

  double CalculateReward() {
      // 权重配置
      const double linkWeights[4] = {0.25, 0.25, 0.25, 0.25};  // 4条链路均权
      const double LOSS_THRESHOLD = 0.25;  // 丢包分档阈值 25%

      for (每条链路 i) {
          // ═══════════════════════════════════════════
          // A. 吞吐量改善量 (权重 0.2)
          // ═══════════════════════════════════════════
          double tImp = (throughput - prevThroughput) / prevThroughput;

          // ═══════════════════════════════════════════
          // B. 延迟改善量 (权重 0.3)
          // ═══════════════════════════════════════════
          double dImp = (prevDelay - delay) / prevDelay;  // 延迟降低为正

          // ═══════════════════════════════════════════
          // C. 丢包贡献 (权重 0.5) - 分档处理
          // ═══════════════════════════════════════════
          double lossContribution;
          if (lossRate < 0.25) {
              // 小丢包: 用改善量 (关注"是否变好")
              lossContribution = (prevLossRate - lossRate) * 0.5;
          } else {
              // 大丢包: 指数级绝对惩罚
              lossContribution = -0.5 * (1 - exp(-(lossRate - 0.25) * 15));
          }

          // 单链路综合奖励
          linkReward = tImp * 0.2 + dImp * 0.3 + lossContribution;
          linkReward = clamp(linkReward, -1.0, 0.5);  // 限幅

          totalReward += linkReward * 0.25;
      }

      // ═══════════════════════════════════════════
      // D. 全局惩罚 (加速模式切换)
      // ═══════════════════════════════════════════
      if (maxLoss > 0.4)      totalReward -= 0.3;  // 重度惩罚
      else if (maxLoss > 0.25) totalReward -= 0.15; // 中度惩罚

      return clamp(totalReward, -1.0, 1.0);
  }

  6. Q 表更新公式

  void Update(state, action, newState, reward) {
      int stateId = StateToId(state);
      int newStateId = StateToId(newState);

      // 标准 Q-Learning 更新公式
      double qPredict = qTable[stateId][action];
      double qTarget = reward + gamma * max(qTable[newStateId]);

      qTable[stateId][action] += alpha * (qTarget - qPredict);
      //                        ─────   ─────────────────
      //                        学习率      TD误差
  }

  7. 周期性决策流程

  void PeriodicDecisionMaking() {
      // 每 3 秒执行一次

      // 1. 获取当前网络状态
      NetworkState currentState = EvaluateNetworkState();

      // 2. 结算上一轮动作 (首次跳过)
      if (!isFirstRun) {
          double reward = CalculateReward();
          m_networkQLearning.Update(lastState, lastAction, currentState,
  reward);
      }

      // 3. 选择新动作
      int action = m_networkQLearning.ChooseAction(currentState);

      // 4. 执行动作
      ExecuteSwitchingAction(action);

      // 5. 记录供下次结算
      lastState = currentState;
      lastAction = action;
      isFirstRun = false;

      // 6. 自调度 (每 3 秒)
      Simulator::Schedule(Seconds(3.0), PeriodicDecisionMaking, this);
  }

  💡 改进建议

  1. 扩展状态空间: 加入吞吐量档位、节点数量等维度
  2. 移除 KEEP 动作: 或赋予实际意义（如延迟切换）

      // 1. 计算平均距离
      for (i = 0; i < nodeCount; i++) {
          for (j = i+1; j < nodeCount; j++) {
              distance = sqrt(dx² + dy² + dz²);  // 欧氏距离
              totalDistance += distance;

      state.averageNodeDistance = totalDistance / pairCount;

  2. CollectFlowStats() 执行流程详解

  std::vector<FlowStatsRecord> ApProtocolInfoApp::CollectFlowStats()
  {
      // ═══════════════════════════════════════════════════════════════
      // Step 1: 检查 FlowMonitor 是否已初始化
      // ═══════════════════════════════════════════════════════════════
      if (!m_monitor || !m_classifier) {
          NS_LOG_WARN("FlowMonitor or Classifier not set!");
          return flowVec;  // 返回空向量
      }

      // ═══════════════════════════════════════════════════════════════
      // Step 2: 获取当前所有流的统计快照
      // ═══════════════════════════════════════════════════════════════
      m_monitor->CheckForLostPackets();  // 标记超时未收到的包为丢失
      std::map<FlowId, FlowMonitor::FlowStats> stats =
  m_monitor->GetFlowStats();

      // ═══════════════════════════════════════════════════════════════
      // Step 3: 计算采样时间间隔
      // ═══════════════════════════════════════════════════════════════
      double currentTime = Simulator::Now().GetSeconds();
      double deltaTime = currentTime - m_lastSampleTime;  // 距上次采样的时间

      // ═══════════════════════════════════════════════════════════════
      // Step 4: 遍历每个流，计算区间统计量
      // ═══════════════════════════════════════════════════════════════
      for (auto const &flow : stats) {

          // 4.1 获取流的五元组信息
          Ipv4FlowClassifier::FiveTuple t = m_classifier->FindFlow(flow.first);
          // t.sourceAddress, t.destinationAddress, t.protocol, 
          // t.sourcePort, t.destinationPort

          uint32_t flowId = flow.first;
          const FlowMonitor::FlowStats &fs = flow.second;

          // ─────────────────────────────────────────────────────────
          // 4.2 计算区间吞吐量
          // ─────────────────────────────────────────────────────────
          uint64_t currentTotalRx = fs.rxBytes;           // 当前累计接收字节
          uint64_t lastRx = m_lastFlowRxBytes[flowId];    // 上次采样的接收字节
          uint64_t deltaRx = currentTotalRx - lastRx;     // 区间增量

          // 吞吐量 = 增量字节数 × 8 (转bit) / 时间间隔 / 1024 (转Kbps)
          uint32_t intervalThrKbps = (deltaRx * 8.0) / (deltaTime * 1024.0);

          // ─────────────────────────────────────────────────────────
          // 4.3 计算区间丢包率
          // ─────────────────────────────────────────────────────────
          uint32_t deltaTxP = fs.txPackets - m_lastFlowTxPackets[flowId];  // 
  区间发送包数
          uint32_t deltaRxP = fs.rxPackets - m_lastFlowRxPackets[flowId];  // 
  区间接收包数

          // 丢包率 = (发送 - 接收) / 发送 × 10000 (放大存储)
          double intervalLoss = (deltaTxP - deltaRxP) / deltaTxP;
          uint16_t scaledLossRate = intervalLoss * 10000;  // 如 0.05 → 500

          // ─────────────────────────────────────────────────────────
          // 4.4 提取平均延迟和抖动
          // ─────────────────────────────────────────────────────────
          // 平均延迟 = 延迟总和 / 接收包数
          uint32_t avgDelayMs = fs.delaySum.GetMilliSeconds() / fs.rxPackets;

          // 平均抖动 = 抖动总和 / (接收包数 - 1)
          uint32_t avgJitterMs = fs.jitterSum.GetMilliSeconds() / (fs.rxPackets
  - 1);

          // ─────────────────────────────────────────────────────────
          // 4.5 封装结果
          // ─────────────────────────────────────────────────────────
          FlowStatsRecord record;
          record.throughputKbps = intervalThrKbps;
          record.delayMs        = avgDelayMs;
          record.jitterMs       = avgJitterMs;
          record.port           = t.destinationPort;  // 用目的端口区分链路
          record.lossRate       = scaledLossRate;

          // ─────────────────────────────────────────────────────────
          // 4.6 更新历史状态 (供下次增量计算)
          // ─────────────────────────────────────────────────────────
          m_lastFlowRxBytes[flowId] = currentTotalRx;
          m_lastFlowTxPackets[flowId] = fs.txPackets;
          m_lastFlowRxPackets[flowId] = fs.rxPackets;
      }

      // ═══════════════════════════════════════════════════════════════
      // Step 5: 更新采样时间
      // ═══════════════════════════════════════════════════════════════
      m_lastSampleTime = currentTime;

      return flowVec;
  }

  3. 数据来源详细说明

  3.1 吞吐量

  ┌─────────────────────────────────────────────────────────────────────────┐
  │                           吞吐量计算原理                                 │
  ├─────────────────────────────────────────────────────────────────────────┤
  │                                                                         │
  │   时间轴:  T0 ──────────────── T1 ──────────────── T2                   │
  │            │                  │                  │                      │
  │   累计接收: 0 bytes          500 bytes        1500 bytes                │
  │            │                  │                  │                      │
  │            └──────── 1秒 ────┘└──────── 1秒 ────┘                       │
  │                                                                         │
  │   区间 [T0, T1]:                                                         │
  │     deltaRx = 500 - 0 = 500 bytes                                       │
  │     throughput = 500 × 8 / 1 / 1024 = 3.9 Kbps                         │
  │                                                                         │
  │   区间 [T1, T2]:                                                         │
  │     deltaRx = 1500 - 500 = 1000 bytes                                   │
  │     throughput = 1000 × 8 / 1 / 1024 = 7.8 Kbps                        │
  │                                                                         │
  │   公式: throughput = (rxBytes_current - rxBytes_last) × 8 / Δt / 1024   │
  │                                                                         │
  └─────────────────────────────────────────────────────────────────────────┘

  3.2 丢包率

  ┌─────────────────────────────────────────────────────────────────────────┐
  │                           丢包率计算原理                                 │
  ├─────────────────────────────────────────────────────────────────────────┤
  │                                                                         │
  │   发送端: ──●──●──●──●──●──●──►  (6 个包)                               │
  │                    ↓                                                    │
  │   丢失:            ✗           (1 个包丢失)                              │
  │                    ↓                                                    │
  │   接收端: ──●──●──●──●──●────►  (5 个包)                                │
  │                                                                         │
  │   丢包率 = (txPackets - rxPackets) / txPackets                          │
  │         = (6 - 5) / 6 = 16.67%                                          │
  │                                                                         │
  │   放大存储: 0.1667 × 10000 = 1667                                       │
  │                                                                         │
  │   区间丢包率 = (deltaTx - deltaRx) / deltaTx                            │
  │             = ((txPackets_t2 - txPackets_t1) -                          │
  │                (rxPackets_t2 - rxPackets_t1)) /                         │
  │               (txPackets_t2 - txPackets_t1)                             │
  │                                                                         │
  └─────────────────────────────────────────────────────────────────────────┘

  3.3 延迟

  ┌─────────────────────────────────────────────────────────────────────────┐
  │                           延迟计算原理                                   │
  ├─────────────────────────────────────────────────────────────────────────┤
  │                                                                         │
  │   发送端时间:  t0      t1      t2      t3                               │
  │               ●───────●───────●───────●──►                               │
  │               │       │       │       │                                 │
  │               │  20ms │  25ms │  18ms │                                 │
  │               │       │       │       │                                 │
  │               ▼       ▼       ▼       ▼                                 │
  │   接收端时间: t0+20  t1+25  t2+18  t3+??                                │
  │                                                                         │
  │   单包延迟 = 接收时间 - 发送时间                                         │
  │                                                                         │
  │   FlowMonitor 记录:                                                     │
  │     delaySum = 20 + 25 + 18 + ... = 所有包延迟总和                      │
  │     rxPackets = 接收到的包数                                             │
  │                                                                         │
  │   平均延迟 = delaySum / rxPackets                                       │
  │            = (20 + 25 + 18) / 3 = 21 ms                                 │
  │                                                                         │
  │   注意: 这是累积平均值，不是区间值！                                     │
  │                                                                         │
  └─────────────────────────────────────────────────────────────────────────┘

  3.4 抖动

  ┌─────────────────────────────────────────────────────────────────────────┐
  │                           抖动 计算原理                          │
  ├─────────────────────────────────────────────────────────────────────────┤
  │                                                                         │
  │   定义: 相邻两个包的延迟差值 (绝对值)                                    │
  │                                                                         │
  │   包序号:    P1      P2      P3      P4                                 │
  │   延迟:      20ms    25ms    18ms    22ms                                │
  │              │       │       │       │                                   │
  │   抖动:      │  |25-20| |18-25| |22-18|                                  │
  │              │    = 5   = 7   = 4  │                                    │
  │              └─────────────────────┘                                     │
  │                                                                         │
  │   jitterSum = |D2-D1| + |D3-D2| + |D4-D3| + ...                         │
  │             = 5 + 7 + 4 = 16 ms                                         │
  │                                                                         │
  │   平均抖动 = jitterSum / (rxPackets - 1)                                │
  │            = 16 / (4 - 1) = 5.33 ms                                     │
  │                                                                         │
  │   注意: n 个包只有 n-1 个抖动值                                          │
  │                                                                         │

  4. 关键代码解析

  // 
  ═════════════════════════════════════════════════════════════════════════════
  // 发送端: SendOutgoingLogger
  // 
  ═════════════════════════════════════════════════════════════════════════════
  void Ipv4FlowProbe::SendOutgoingLogger(const Ipv4Header &ipHeader, 
                                          Ptr<const Packet> ipPayload, 
                                          uint32_t interface) {
      // 1. 检查是否已有 Tag (避免重复标记)
      Ipv4FlowProbeTag fTag;
      if (ipPayload->FindFirstMatchingByteTag(fTag)) {
          return;  // 已有 Tag，跳过
      }

      // 2. 分类五元组，生成 FlowId
      FlowId flowId;
      FlowPacketId packetId;
      if (m_classifier->Classify(ipHeader, ipPayload, &flowId, &packetId)) {

          // 3. 记录发送事件
          uint32_t size = ipPayload->GetSize() + ipHeader.GetSerializedSize();
          m_flowMonitor->ReportFirstTx(this, flowId, packetId, size);
          //                            ↑ 记录: txPackets++, txBytes+=size, 
  时间戳

          // 4. 打上 Tag，供后续节点识别
          Ipv4FlowProbeTag tag(flowId, packetId, size, 
                               ipHeader.GetSource(), 
                               ipHeader.GetDestination());
          ipPayload->AddByteTag(tag);
      }
  }

  // 
  ═════════════════════════════════════════════════════════════════════════════
  // 接收端: ForwardUpLogger
  // 
  ═════════════════════════════════════════════════════════════════════════════
  void Ipv4FlowProbe::ForwardUpLogger(const Ipv4Header &ipHeader, 
                                       Ptr<const Packet> ipPayload, 
                                       uint32_t interface) {
      // 1. 读取 Tag
      Ipv4FlowProbeTag fTag;
      if (!ipPayload->FindFirstMatchingByteTag(fTag)) {
          return;  // 没有 Tag，说明发送端未被监控
      }

      // 2. 验证源/目的地址
      if (!fTag.IsSrcDstValid(ipHeader.GetSource(), ipHeader.GetDestination()))
  {
          return;  // 地址不匹配 (可能是隧道封装)
      }

      // 3. 记录接收事件
      FlowId flowId = fTag.GetFlowId();
      FlowPacketId packetId = fTag.GetPacketId();
      uint32_t size = ipPayload->GetSize() + ipHeader.GetSerializedSize();

      m_flowMonitor->ReportLastRx(this, flowId, packetId, size);
      //                            ↑ 记录: rxPackets++, rxBytes+=size
      //                            ↑ 计算: delay = now - txTime
      //                            ↑ 累加: delaySum += delay, jitterSum += 
  |delay-lastDelay|
  }

  4. 动作选择策略

  ┌─────────────────────────────────────────────────────────────────────────────
  ────────┐
  │                         动作选择策略 - 动态 ε-Greedy
          │
  └─────────────────────────────────────────────────────────────────────────────
  ────────┘

    核心创新: 根据丢包率动态调整探索率 ε

    ┌───────────────────────────────────────────────────────────────────────────
  ──────┐
    │  int ChooseAction(const NetworkState& state) {
        │
    │      int stateId = StateToId(state);
        │
    │
        │
    │      // ═══════ 动态 ε 计算 ═══════
        │
    │      double dynamicEpsilon;
        │
    │      if (state.maxLossRate <= 0.05) {       // 稳定态: ≤5%
        │
    │          dynamicEpsilon = baseEpsilon * 0.5; // 0.2 × 0.5 = 0.1
        │
    │      } else if (state.maxLossRate <= 0.20) {// 轻度拥塞: 5%~20%
        │
    │          dynamicEpsilon = baseEpsilon * 1.5; // 0.2 × 1.5 = 0.3
        │
    │      } else {                                // 重度拥塞: >20%
         │
    │          dynamicEpsilon = baseEpsilon * 3.0; // 0.2 × 3.0 = 0.6
        │
    │      }
        │
    │      dynamicEpsilon = clamp(dynamicEpsilon, 0.0, 1.0);
        │
    │
        │
    │      // ═══════ 探索 ═══════
        │
    │      if (rand() / RAND_MAX < dynamicEpsilon) {
        │
    │          return rand() % 2;  // 随机返回 0 或 1 (不含 KEEP!)
        │
    │      }
        │
    │
        │
    │      // ═══════ 利用 ═══════
        │
    │      int bestAction = 0;
        │
    │      double maxQ = qTable[stateId][0];
        │
    │      for (int a = 1; a < 3; a++) {
        │
    │          if (qTable[stateId][a] > maxQ) {
        │
    │              maxQ = qTable[stateId][a];
        │
    │              bestAction = a;
        │
    │          }
        │
    │      }
        │
    │      return bestAction;
        │
    │  }
        │
    └───────────────────────────────────────────────────────────────────────────
  ──────┘

    动态 ε 曲线:

       ε
       │
     0.6├─────────────────────────────────●━━━━━━━━━━━━━━
       │                                ╱
     0.3├─────────────────────●─────────╱
       │                    ╱
     0.1├─────●─────────────╱
       │    ╱
     0.0├───┴───────┴───────┴───────┴───────┴──────▶ 丢包率
            5%      20%      40%
         (稳定)  (轻度)   (重度)

    设计意图:
    ┌───────────────────────────────────────────────────────────────────────────
  ──────┐
    │  · 网络稳定时 (丢包≤5%):   ε=0.1，少探索，多利用已学到的策略
        │
    │  · 轻度拥塞时 (丢包5~20%): ε=0.3，中等探索，尝试寻找更好策略
        │
    │  · 重度拥塞时 (丢包>20%):  ε=0.6，多探索，积极尝试不同策略
        │
    └───────────────────────────────────────────────────────────────────────────
  ──────┘

  5. 奖励函数设计

  ┌─────────────────────────────────────────────────────────────────────────────

          │

    权重分配:
    ┌───────────────────────────────────────────────────────────────────────────
  ──────┐
    │
        │
    │   单链路奖励 = 吞吐改善×0.2 + 延迟改善×0.3 + 丢包贡献×0.5
         │
    │
        │
    │   总奖励 = Σ(单链路奖励 × 0.25) + 全局惩罚
        │
    │
        │
    └───────────────────────────────────────────────────────────────────────────
  ──────┘

    丢包分档处理 (核心设计):
    ┌───────────────────────────────────────────────────────────────────────────
  ──────┐
    │
        │
    │   if (lossRate < 25%) {
        │
    │       // 小丢包: 用改善量 (关注"是否变好")
        │
    │       lossContribution = (prevLossRate - lossRate) × 0.5;
        │
    │       // 丢包降低 → 正奖励
        │
    │   } else {
        │
    │       // 大丢包: 指数级绝对惩罚 (关注"当前状态有多糟")
        │
    │       lossContribution = -0.5 × (1 - e^(-(lossRate - 0.25) × 15));
       │
    │       // 丢包越严重，惩罚越重，渐近于 -0.5
        │
    │   }
        │
    │
        │
    └───────────────────────────────────────────────────────────────────────────
  ──────┘

  6. Q 表更新

  ┌─────────────────────────────────────────────────────────────────────────────
  ────────┐
  │                              Q 表更新公式
          │
  └─────────────────────────────────────────────────────────────────────────────
  ────────┘

    标准 Q-Learning 更新:
    ┌───────────────────────────────────────────────────────────────────────────
  ──────┐
    │
        │
    │  Q(s, a) ← Q(s, a) + α × [r + γ × max_a'Q(s', a') - Q(s, a)]
       │
    │           │          │    │   │                    │
        │
    │           │          │    │   │                    └── 当前估计值
        │
    │           │          │    │   └── 新状态下的最大Q值
         │
    │           │          │    └── 折扣因子 (0.6)
         │
    │           │          └── 即时奖励
         │
    │           └── 学习率 (0.4)
         │
    │
        │
    └───────────────────────────────────────────────────────────────────────────
  ──────┘

    代码实现:
    ┌───────────────────────────────────────────────────────────────────────────
  ──────┐
    │  void Update(state, action, newState, reward) {
        │
    │      int stateId = StateToId(state);
        │
    │      int newStateId = StateToId(newState);
        │
    │
        │
    │      double qPredict = qTable[stateId][action];
        │
    │      double qTarget = reward + gamma * max(qTable[newStateId]);
        │
    │
        │
    │      qTable[stateId][action] += alpha * (qTarget - qPredict);
        │
    │  }
        │
    └───────────────────────────────────────────────────────────────────────────
  ──────┘

    参数配置:
    ┌───────────────────────────────────────────────────────────────────────────
  ──────┐
    │  · alpha (学习率) = 0.4    → 较高，快速学习新经验
       │
    │  · gamma (折扣因子) = 0.6  → 中等重视未来奖励
       │
    │  · epsilon (基础探索率) = 0.2 → 动态调整
       │
    └───────────────────────────────────────────────────────────────────────────
  ──────┘

  8. 设计优缺点分析

  ┌─────────────────────────────────────────────────────────────────────────────
  ────────┐
  │                              设计优缺点分析
          │
  └─────────────────────────────────────────────────────────────────────────────
  ────────┘

    ✅ 优点:
    ┌───────────────────────────────────────────────────────────────────────────
  ──────┐
    │  1. 动态 ε 探索: 网络差时多探索，好时多利用，加速收敛
        │
    │  2. 丢包分档处理: 小丢包关注改善，大丢包强力惩罚，避免策略震荡
        │
    │  3. 多指标奖励: 综合吞吐/延迟/丢包，不偏废单一指标
        │
    │  4. 全局惩罚: 任何链路严重丢包都触发额外惩罚
        │
    │  5. 周期性决策: 3秒间隔给网络足够反应时间
        │
    └───────────────────────────────────────────────────────────────────────────
  ──────┘

    ⚠️ 问题:
    ┌───────────────────────────────────────────────────────────────────────────
  ──────┐
    │  1. 状态空间过小 (仅4状态):
        │
    │     · 只有距离和丢包两个维度
        │
    │     · 无法精确表达网络复杂性
        │
    │     · 不同网络状况可能映射到同一状态
        │
    │
        │
    │  2. KEEP 动作形同虚设:
        │
    │     · 探索时 rand() % 2 只返回 0 或 1，不含 2
        │
    │     · Q 表初始化为 0，KEEP 很难被选中
       │
    │     · 实际上只有 MULTI 和 ADHOC 两个有效动作
       │
    │
        │
    │  3. 动作含义不对称:
        │
    │     · MULTI 动作: 几乎无操作 (只更新 m_currentMode)
        │
    │     · ADHOC 动作: 调用 SetRPtoAll() + ChangeDeviceLogical(1)
       │
    │     · 从 MULTI→ADHOC 有实际操作，反向却没有
       │
    │
        │
    │  4. 奖励延迟问题:
        │
    │     · 模式切换后需要时间生效
        │
    │     · 3秒的决策间隔可能不足以观察效果
       │
    │     · 奖励计算用的是当前状态，不是动作执行后的状态
        │
    │
        │
    │  5. 冷启动问题:
        │
    │     · Q 表初始全为 0
        │
    │     · 前几轮决策基本随机
        │
    │     · 没有预训练或启发式初始化
        │
    └───────────────────────────────────────────────────────────────────────────
  ──────┘
